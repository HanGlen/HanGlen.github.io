DND 助手是我一个人做的跑团小程序，有 1.4 万用户。2026 年 6 月起，我基本不再自己写代码，改成管理一组 AI Agent：Claude、Codex、Trae，还有几个只做分诊、提议的小任务。四个半月合入了 1,326 个 PR。

这篇写我觉得最关键的几件事。

## 1. 先把 GitHub 变成团队的大脑

AI 没有记忆，每次运行都是新会话。所以所有状态必须在 GitHub 上：

- **Issue 是任务队列。** 我在手机上随手开 Issue，玩家反馈也会被初筛 Agent 转成 Issue。
- **标签是调度信号。** 分诊 Agent 给每个 Issue 打齐类型、优先级（P0–P2）、难度三类标签，执行 Agent 按标签挑活。
- **PR 是交付物。** 每个 PR 正文必须写「一句话说明」和「问题来源」，给我看，也给下一个接手的 AI 看。
- **评论是交接记录。** 认领、完成一片、卡住了，都按固定格式写在 Issue 下面。

## 2. 按能力分工，不按「谁有空」

不同模型擅长的事不一样。现在的分工是：

| 角色 | 负责 |
|---|---|
| Claude | 需求分析、产品取舍、PRD、交互和 UI |
| Codex | 云函数、数据库、接口、规则计算 |
| 另一家模型 | 代码评审，每个 PR 最多两轮 |
| 我 | 定方向、给授权、真机验收、合并 |

前后端都要改的需求，先由 Claude 写 PRD、定接口契约，再拆成两张子单。这样不会出现一个 AI 半懂不懂地把前后端一起改了。

## 3. 规则写成代码，改一处全员生效

所有 AI 共用一份 `AGENTS.md`，限 60 行，只写红线和索引；细节放到 `docs/` 里的手册。定时任务的提示词只写「你是谁、领什么难度」几行，其余都指向手册。

好处是：我想改一条规则，只改手册，合入后所有 Agent 下次运行就照新规则做，不用去五个软件里分别改提示词。

## 4. 门禁兜底，不靠提醒

AI 犯过的错，我不会只在提示词里写「下次注意」，而是写成一条门禁。现在有 183 道检查，比如：

- 判断机制时按名字写死（比如 `if (name === '圣武士')`）→ 被 `check:no-hardcoded-name` 拦下。
- 译名和社区通用的不一致 → `check:translation`。
- 主包超过微信 2MB 上限 → `check:package-size`。

门禁不过就不能合并，而且**不许为了过 CI 去改 CI**。

## 5. 哪些事必须留给人

AI 能把 PR 整理到「可以合并」，但这几件事一定要我点头：

- 合并到上线分支
- 上传和发布小程序
- 涉及收费、隐私、不可逆的操作

AI 拿不准方向时，给 Issue 打 `needs-decision`，在评论里写清要我回答的问题，而不是自己猜。

## 6. 一切可观测

每个定时任务每次运行完，都要在一个日志 Issue 下留一条固定格式的回执：`【任务名】结果：成功｜失败｜无可做项`。看板读这些回执显示状态，两个周期没回执就标「数据过期」。

这样我不用盯着，只看看板就知道谁在干活、谁卡住了。

## 还没解决的问题

- **评审成本。** AI 评审偶尔会挑出不重要的问题，所以限制了每个 PR 最多两轮。
- **真机验收。** UI 改动还得我拿手机看，这一步暂时没法自动化。
- **上下文。** 项目越大，AI 每次读规则的成本越高，手册需要不断精简。
