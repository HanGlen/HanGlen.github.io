## 1. 讲什么

**主题：企业怎么落地定制软件。** 定制软件包括两类：传统的数字化软件（表单、流程、小程序、管理后台），和软件里的 AI 功能（问答、生成、审核）。

**解决三个痛点**，每个痛点一页：

| 痛点 | 老板的原话大概是 | 页面 |
|---|---|---|
| 怎么做出来 | 「外面报价几千到几十万，做出来的东西还不一定能用」 | 03 |
| 怎么维护和迭代 | 「做完交付就没人管了，改个小地方要等一个月」 | 04 |
| 怎么用上 AI 能力 | 「AI 很火，但不知道怎么放进自己的软件里，怕乱答、怕花钱」 | 05 |

**贯穿全场的一句：AI 让这两样（数字化软件、AI 功能）都变快、变便宜了。** 每一页的案例都是车主自己的小程序，用真数字证明「一个人带一支 AI 研发团队」做得到。

**读者：** 台下多是非技术出身、用过 AI 的中小企业老板。术语可以出现（会显得专业），但每个术语后面紧跟一句大白话。

## 3. 每页写什么

### 01 我是谁
- 一张关系图，中间是「我」，周围的点**默认全部正常显示**，不用一个个点亮；悬停只是弹出右边卡片。
- **颜色 = 分组，相近的放一起**（车主 2026-11-17 定）：
  - 学校（左上）：西电本硕、应激监测系统
  - 工作（右上）：华为、比亚迪。只写「华为」，不写「华为 OD」，图上不标时间；**两个点各自连「我」，互相不连**
  - 跑团（右下）：洛山达 DND 助手、冒险匣子（店家合作，订制规则）、晨曦酒馆、装修工作室 · 跑团店、一家在谈的跑团店（订制规则）。两家跑团店都**直接连「我」**
  - 现在合作（左下）：G School 教育、交通运输行业（吊车租赁平台，我负责推进）、外贸行业（平台开发，在谈）。不写公司名，也不写「先不写名字」
- **形状 = 状态**：实心已上线、空心进行中、虚线在谈。学校和工作不叫「已上线」：卡片写已毕业、已完成、曾任职（`statusText`）。
- 点的圆心要压在连线端点上，文字挂在点下面。不加收尾句。

### 02 企业的数字化和 AI，做到哪了
- **主旨一句话：人人都在用 AI，企业还没把它用进业务。** 不用「地基 / 楼」的比喻（车主看不懂）。
- 一张横条图，同一把 0–100% 的尺子；蓝 = 数字化，陶土红 = AI。← → 一行行亮，没讲到的行先淡着，结论讲完最后一行才出来。
  - 个人：用过生成式 AI 超 50%，7 亿多人（CNNIC，车主要求保留这个数）
  - 工业企业：用上数字化研发设计工具 86%，用上 AI 超 30%（同一场工信部发布会）
  - 中小企业：数字化走出基础信息化约 13%；在用 AI 50% → 用进核心业务约 14%
- 结论：差的就是「用进业务」，这正是定制软件要做的事。来源编号写在页底。

### 03 怎么做出来（六步，从小到大）
先抛问题，再给图。右栏只放：一个问题、一句大白话、一个例子；依据点开才看。

| 步 | 概念 | 问题 / 图 |
|---|---|---|
| 工具准备 | Tools | 写代码的 AI（Claude Code、Codex、Trae）、GitHub、Linear、飞书表格；挑模型的四个榜 |
| 地基 | Harness | 攀岩比喻：模型是攀岩的人，Harness 是绳子和安全带（仓库、规则文档、自动检查、工程规范） |
| 一张单 | Spec | 「最简单的一个改动，怎么做？」上面一行专业说法，**每一步下面直接是同一个过程的真实例子**（灵感 → 激励）；**代码评审、门禁检查任一不过都打回重改** |
| 一个大需求 | Slices + Loop | 「大一点的需求呢？」AI 需求分析 → 切成小单 → 每个 AI 定时开工一轮领一张，循环做完 |
| 一堆需求 | Triage | 「一堆大需求怎么办？」分诊 AI：接需求、切成最小可执行单、排好领取顺序 → 任务池 → 几个 AI 轮班领 |
| 推荐流程 | Workflow | 讲清需求（一句话说清定位，细节讲清楚、不用整理）→ 交给开发 → 做完 → 差不多就上线 → 反馈更新（下一页） |

- 车主说的「home rope」暂按攀岩比喻里的「绳子」理解（Harness = 安全带和绳子），出处是 Tejas Kumar 在 AI Engineer World's Fair 的演讲（经 basic-harness 文档转引），**待车主确认**。「graph engineering」仍未对上，不上页面。

### 04 怎么维护和迭代
用户提反馈 → AI 审核（回到用户）→ 开发 → 上线告诉用户（回到用户）；下面一排是定时任务。实例：10 月 29 日一条反馈 2.5 小时合入。

### 05 怎么用上 AI 能力
- 案例：小程序的「规则问答」（2026-11 上线）。玩家用大白话问，AI 分四步答：理解问题 → 在 35 本规则书原文里检索 → 回答 → 逐句核对，每句附原文出处；查不到就说没找到。
- 对企业的对应：把「规则书」换成公司的制度、产品手册、合同模板。
- 三条落地要点：答案带出处、答错能报错、按次计费有上限。
- 截图用 `public/shots/talk/rules-qa.jpg`（来自 dnd-miniprogram `marketing/shots/rules-qa/`）。

### 06 找人做定制软件，先问这五句
仓库归谁、有没有规则文档、有没有自动检查、问题怎么跟踪、改一个小问题要多久。

一句话总结 + 二维码（放网站还是微信）。

## 4. 设计

**标杆：Antigravity 官网**（车主 2026-11-17 指定）。学它的几点：
- 大留白、大字号，一屏只讲一件事。
- **每次切换都有过渡**：上下翻页时，旧页向上淡出、轻微模糊缩小，新页从下方带模糊浮上来；左右切换时，内容按方向横向滑入。标题、正文、图表错峰出现（相差 60–80ms）。
- 缓动统一用 `cubic-bezier(0.2, 0.8, 0.2, 1)`，翻页 0.7s 左右，页内切换 0.45s 左右。
- 背景有会动的东西（封面的 PR 点阵），其他页面克制。

其余沿用网站规矩：米白纸色、衬线标题、陶土红强调色；颜色只用 `global.css` 的令牌；投影时固定浅色。

## 5. 交互

- 上下翻页：↑ ↓ / PageUp PageDown / 空格 / 滚轮 / 翻页笔 / 手机上下滑；地址栏 `#3` 直接到第 3 页，刷新不丢页。
- 页内切换：← → 或悬停、点击；每页都要能只用键盘讲完。
- `P` 打开讲者备注。
- 手机（≤ 900px）退回普通滚动，不做整页过渡；390px 不能横向滚动。
- `prefers-reduced-motion` 时关掉全部过渡。

## 6. 内容规矩

- **一屏的字要少**：一屏一个主角，主次分明；细节用渐进披露（← →、悬停、点开），讲的话放备注。

- **依据只用一手来源。** 车主给的三个 B 站视频：Matt Pocock 那个能对上本人 2026-11-12 的原帖，用了；另外两个是搬运，搜不到原始出处，改用 Anthropic 工程博客原文。
- 车主的经历以 digital-me 和对话为准，不编。在谈的合作只写行业，不写公司名；人名、学历只口头讲。
- 案例统一用自己的小程序；交通运输行业那家不当案例讲。
