## 1. 讲什么

**主题：企业怎么落地定制软件与 AI 能力**（车主 2026-11-17 晚定，原为「企业怎么落地定制软件」，主题要把 AI 带上）。 定制软件包括两类：传统的数字化软件（表单、流程、小程序、管理后台），和软件里的 AI 功能（问答、生成、审核）。

**解决三个痛点**，每个痛点一页：

| 痛点 | 老板的原话大概是 | 页面 |
|---|---|---|
| 怎么做出来 | 「外面报价几千到几十万，做出来的东西还不一定能用」 | 03 |
| 怎么维护和迭代 | 「做完交付就没人管了，改个小地方要等一个月」 | 04 |
| 怎么用上 AI 能力 | 「AI 很火，但不知道怎么放进自己的软件里，怕乱答、怕花钱」 | 05 |

**贯穿全场的一句：AI 让这两样（数字化软件、AI 功能）都变快、变便宜了。** 每一页的案例都是车主自己的小程序，用真数字证明「一个人带一支 AI 研发团队」做得到。

**读者：** 台下多是非技术出身、用过 AI 的中小企业老板。术语可以出现（会显得专业），但每个术语后面紧跟一句大白话。

## 3. 每页写什么

### 01 自我介绍
- 标题下面不加说明句（车主 2026-11-17：「中间是我……」那句删掉）。
- 一张关系图，中间是「我」，周围的点**默认全部正常显示**，不用一个个点亮；悬停只是弹出右边卡片。
- **颜色 = 分组，相近的放一起**（车主 2026-11-17 定）：
  - 学校（左上）：西电本硕、西电 · 第四军医大校企联合项目（「企」是第四军医大那边的军工企业，车主 2026-11-17 确认）
  - 工作（右上）：华为、比亚迪。只写「华为」，不写「华为 OD」，图上不标时间；**两个点各自连「我」，互相不连**
  - 跑团（右下）：洛山达 DND 助手（图上第二行写「微信小程序」）、冒险匣子（第二行写「跑团店定制规则」）、自媒体（卡片里才写晨曦酒馆，配第一条视频封面）、装修工作室 · 跑团店、一家在谈的跑团店（定制规则）。两家跑团店都**直接连「我」**
  - 现在合作（左下）：G School 教育、吊车租赁平台（我负责推进）、外贸平台（在谈）。不写公司名，也不写「先不写名字」
- **形状 = 状态**：实心已上线、空心进行中、虚线在谈。学校和工作不叫「已上线」：卡片写已毕业、已完成、曾任职（`statusText`）。
- 点的圆心要压在连线端点上，文字默认挂在点下面；DND 助手的字挂右边、在谈的跑团店挂上面，避开连线。**连线不能交叉**：晨曦酒馆、装修工作室挂在 DND 助手外侧，冒险匣子、在谈的跑团店直连「我」从上方走。不加收尾句。

### 02 AI 和数字化，用到多深了
- **四块都用中国数据**（车主 2026-11-17 定；HAN-1819 调研、HAN-1822 改页）。美国 / 全球的数只放讲者备注。
- 每块第一行是 100%（底色格子），写明 100% 是谁。同一份调查里套不进去的层就空着，不拿另一份调查凑（所以四块是 3 / 2 / 2 / 3 层）。
- **一个主题、多个比例**（车主 2026-11-17 定）：四块 10 × 10 色块图，每格 1%；同一块里数从大到小、颜色从浅到深，后一个数落在前一个里面。蓝 = 数字化，陶土红 = AI。← → 一个数一个数讲，没讲到的块先淡着，最后一个数讲完出结论。
  - 个人用 AI（腾讯研究院 2026-03，2,012 位网民，偏年轻、高学历）：3 个月内用过 95.6% → 每周用好几次 78.7% → 每天都用 30.1%；虚线行：全国用过生成式 AI 超 50%（CNNIC，车主要求保留）
  - 上班用 AI（ADP 2026-07，中国员工）：每周用好几次 73% → 几乎每天用 26%
  - 企业数字化（中信联、点亮智库，10 万余家，数据年份 2025）：靠数据跑业务 15% → 全部业务打通 1.7%
  - 企业用 AI（信通院 2026-03，6,000 余家中小企业）：已经在用 50% → 用进核心业务 13.6% → 嵌进全部流程 2%
- 结论：用 AI 的人已经很多，用进业务的企业还很少，这正是定制软件要做的事。来源编号写在页底。

### 03 怎么做出来（五步，从小到大）
先抛问题，再给图。右栏只放两层：一个问题、一句备注。每步的例子统一放在底部一条独立色块里，依据在色块右边点开才看（车主 2026-11-17）。

依据：`docs/research/talk-03-tools.md`（HAN-1820）、`docs/research/talk-03-harness.md`（HAN-1821），页面 HAN-1823 已按调研改。

| 步 | 概念 | 问题 / 图 |
|---|---|---|
| 工具准备 | Tools | 「先看需求，再挑工具」：一张表，类型 × 入门 / 进阶，五类。写代码的 AI：WorkBuddy、Trae → Claude Code、Codex；放代码直接用 GitHub；管任务：GitHub Issues → Linear；工作流：飞书自动化 → GitHub Actions；放上线：微信云开发。下面挑模型的四个榜 |
| 地基 | Harness | 「工具外面，还要加什么？」三圈：中间模型（负责想）；中圈现成 Harness，Claude Code、Codex，自带工具、循环、权限、上下文；外圈你加上的规矩（沉淀下来的经验）：规则文档、自动检查、技能说明、任务记录。悬停或点一个词，下面一行说它指什么。不用攀岩比喻 |
| 一张单 | Spec | 「最简单的一个改动，怎么做？」上面一行专业说法，**每一步下面直接是同一个过程的真实例子**（灵感 → 激励）；**代码评审、门禁检查任一不过都打回重改** |
| 一个大需求 | Project + Loop | 「大一点的需求呢？」横着一条线：Project（一个大需求）→ AI 需求分析 → 切成小单 → 定时任务（每轮领一张，里面就是上一步那张单）→ 全部合入。下面一行：不同的 AI 擅长不同的单，Claude 前端、界面，Codex 后端、美术 |
| 一堆需求 | Triage | 「一堆大需求怎么办？」虚线框把一堆需求框起来 → 分诊 AI → 一个个 Project（里面全是最小的单）→ 定时任务一直跑 → 合入 |

### 04 怎么维护和迭代
用户提反馈 → AI 审核（回到用户）→ 开发 → 上线告诉用户（回到用户）；下面一排是定时任务。实例：10 月 29 日一条反馈 2.5 小时合入。

### 05 怎么用上 AI 能力
- 案例：小程序的「规则问答」（2026-11 上线）。玩家用大白话问，AI 分四步答：理解问题 → 在 35 本规则书原文里检索 → 回答 → 逐句核对，每句附原文出处；查不到就说没找到。
- 对企业的对应：把「规则书」换成公司的制度、产品手册、合同模板。
- 三条落地要点：答案带出处、答错能报错、按次计费有上限。
- 截图用 `public/shots/talk/rules-qa.jpg`（来自 dnd-miniprogram `marketing/shots/rules-qa/`）。

### 06 找人做定制软件，先问这五句
仓库归谁、有没有规则文档、有没有自动检查、问题怎么跟踪、改一个小问题要多久。

## 4. 设计

**标杆：Antigravity 官网**（车主 2026-11-17 指定）。学它的几点：
- 大留白、大字号，一屏只讲一件事。
- **每次切换都有过渡**：上下翻页时，旧页向上淡出、轻微模糊缩小，新页从下方带模糊浮上来；左右切换时，内容按方向横向滑入。标题、正文、图表错峰出现（相差 60–80ms）。
- 缓动统一用 `cubic-bezier(0.2, 0.8, 0.2, 1)`，翻页 0.7s 左右，页内切换 0.45s 左右。
- 背景有会动的东西（封面的 PR 点阵），其他页面克制。

其余沿用网站规矩：米白纸色、衬线标题、陶土红强调色；颜色只用 `global.css` 的令牌；投影时固定浅色。

## 6. 内容规矩
